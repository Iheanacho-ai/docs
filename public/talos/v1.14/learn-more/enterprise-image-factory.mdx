Enterprise Image Factory is Sidero's authenticated image delivery service for Talos
Enterprise Linux, hosted at `factory.siderolabs.com`. It is a separate product from the
public [Image Factory](/talos/v1.13/learn-more/image-factory) at `factory.talos.dev`.

Though the two services do share a codebase and the same core API (schematics, HTTP, PXE, and
registry frontends), they differ in the following ways:

- `factory.talos.dev` is anonymous and unauthenticated. It is the distribution mechanism
  for open-source Talos Linux.
- `factory.siderolabs.com` requires authentication and is the delivery channel for Talos
  Enterprise Linux artifacts: FIPS-enabled builds, per-schematic SBOMs, VEX data, and
  build attestation.

## Tier availability

Talos Enterprise Linux is available to customers on the Enterprise, Enterprise On-Prem,
Edge, Edge On-Prem, and Talos Enterprise Linux Support tiers. It is also bundled into the
FIPS product, a separate tier for customers who need FIPS 140-3 (CMVP) certified builds,
on top of everything included in Talos Enterprise Linux. Customers on the Talos
Enterprise Linux Support tier authenticate to Enterprise Image Factory directly, without
an Omni account.

## Feature comparison

The table below summarizes what each service provides. Each row is covered in more
detail under [Features](#features).

| | `factory.talos.dev` (public) | `factory.siderolabs.com` (Enterprise) |
|---|---|---|
| Authentication | None | Required |
| Tier access | All Talos Linux users | Enterprise, Enterprise On-Prem, Edge, Edge On-Prem, Talos Enterprise Linux Support, FIPS |
| Schematics, HTTP/PXE/registry frontends | Yes | Yes |
| FIPS-enabled builds | No | Yes, on every build (Talos 1.13+) |
| Per-schematic SBOM (SPDX) | No | Yes |
| VEX data | No | Yes |
| Vulnerability scan reports | No | Yes (`.json`, `.table`, `.sarif`, `.cdx`) |
| Build attestation | No | Yes |
| Custom/private extensions in a schematic | Yes (no attribution) | Yes, with SBOM tier attribution |
| Custom Talos base (customer-signed) | No | Yes |
| On-premises deployment | No | Yes |
| Omni-session authentication | N/A | Yes |

## Features

This section covers each Talos Enterprise Linux artifact and capability in more detail:
FIPS-enabled builds, SBOM, VEX, vulnerability scan reports, build attestation, custom
and private extensions, extension tiers, deployment, and authentication.

### FIPS

Every build served from Enterprise Image Factory is FIPS-enabled by default for Talos
1.13 and later. FIPS (Federal Information Processing Standards) builds use
FIPS-validated cryptographic modules in non-strict mode: WireGuard and other
non-FIPS-validated cryptography continue to work normally alongside them.

FIPS-enabled builds require no separate opt-in or gating step — any build pulled from
Enterprise Image Factory has this property. This is a compliance attribute rather than a
stronger security posture, since FIPS (NIST/CMVP) is a US-specific certification scheme.

FIPS-enabled builds are distinct from FIPS 140-3 (CMVP) certification and strict/enforcing
FIPS mode, which are a separate product offering for customers with formal certification
requirements (for example, US federal buyers).

Enterprise Image Factory is the delivery channel for FIPS-enabled builds, and every
build it serves is FIPS-enabled. Customers who want the other Talos Enterprise Linux
features (SBOM, VEX, build attestation) get FIPS-enabled builds as part of that, whether
or not FIPS itself is a requirement for them.

### SBOM

Enterprise Image Factory generates a per-schematic SBOM in SPDX 2.3 format, covering the
full image — the Talos base and all configured extensions — for a given schematic and
Talos version.

Download the SBOM for a schematic, version, and architecture:

```shell
curl <enterprise-factory-host>/spdx/<schematic>/<version>/<arch> -o image.spdx.json
```

This differs from the SBOMs published with each Talos Linux release on GitHub, which
cover only the unmodified base OS. A per-schematic SBOM is matched to the exact image a
customer is running, including any extensions.

The resulting document can be consumed directly by vulnerability scanners such as Grype:

```shell
grype sbom:image.spdx.json
```

Components contributed by customer-provided extensions or a customer-built base are
attributed separately in the SBOM, distinguishing them from Sidero-maintained components.

SPDX bundles are available for Talos versions v1.11.0 and later.

### VEX

Enterprise Image Factory serves Vulnerability Exploitability eXchange (VEX) data per
Talos Linux release.

Download the VEX document for a Talos version:

```shell
curl <enterprise-factory-host>/vex/<version>/vex.json -o talos.vex.json
```

VEX statements declare whether a given CVE actually applies to a given Sidero artifact,
which lets scanners and admission controllers suppress non-exploitable CVE matches
without resorting to a blanket waiver. VEX data is Sidero-curated and signed per
statement.

Used together with a schematic's SBOM to scan with VEX data applied:

```shell
grype sbom:image.spdx.json --vex talos.vex.json
```

VEX data for Talos Linux is available exclusively through Enterprise Image Factory.

### Vulnerability scan reports

Enterprise Image Factory can return a vulnerability scan report for a given schematic,
version, and architecture, computed on demand against the current vulnerability
database.

Download a scan report for a schematic, version, and architecture, in one of the
supported formats below:

```shell
curl <enterprise-factory-host>/scans/<schematic>/<version>/<arch>/report.json
```

Supported report formats:

- `.json` — output format of the underlying scanner
- `.table` — human-readable table
- `.sarif` — SARIF format
- `.cdx` — CycloneDX format

Because the scan runs against a live vulnerability database rather than being baked in
at build time, the result reflects the image's vulnerability state at request time, not
at the time it was built.

### Build attestation

Every image Enterprise Image Factory builds is accompanied by a signed attestation
recording what went into the build (a bill of materials) and that the build was scanned
for known vulnerabilities. The attestation describes build provenance — what was used to
produce the image — and is not itself a guarantee that an image has zero vulnerabilities.

### Custom and private extensions

The public Image Factory already accepts arbitrary OCI extension images in a schematic.
Enterprise Image Factory adds two capabilities on top of this for customers who need
them:

**Custom extensions.** A customer registers a private OCI registry with Enterprise
Image Factory, scoped to their own namespace, and references their own extension images
in a schematic alongside official and enterprise extensions. The Talos base is
unmodified; Sidero builds, signs, and attests to the assembled image. The per-schematic
SBOM attributes customer-supplied components separately so the assurance boundary is
explicit — Sidero's signature attests to the build pipeline, not to the contents of
unverified customer code.

**Custom builds.** When the Talos base itself is modified — a custom kernel, for
example — the customer is the builder of record and signs the resulting artifacts
themselves. Enterprise Image Factory still serves as the assembly pipeline and OCI
delivery surface, but Sidero's attestation does not extend to a base it didn't produce.

Most Talos Enterprise Linux customers don't need either capability and consume Sidero's
standard builds directly.

### Extension tiers

Talos defines three extension tiers on the public Image Factory: Core and Extra (both
maintained by Sidero Labs, with CVE scanning and SBOM coverage), and Contrib
(community-maintained, with no CVE scanning or SBOM coverage).

Enterprise Image Factory adds:

- **Enterprise extensions** — built and maintained by Sidero Labs, distributed
  exclusively through Enterprise Image Factory. This includes vendor-partnered
  extensions Sidero builds for third-party vendor software that customers can't easily
  build themselves, such as Pure Storage and Portworx (px-fuse) kernel modules.
- **Customer extensions** — built by the customer; see Custom and private extensions
  above.

Contrib extensions remain available on Enterprise Image Factory, since customers may
already depend on them, but they're excluded from SBOM aggregation and VEX coverage and
are marked in the SBOM as community-maintained and unattested.

### Deployment

Enterprise Image Factory can run:

- **Hosted by Sidero**, at `factory.siderolabs.com` — used by SaaS customers and
  Omni-managed customers on a qualifying tier.
- **On-premises**, in the customer's own environment, bundled with Omni or standalone.
  An on-premises instance keeps its backing registry in sync with Sidero's official
  Talos Enterprise Linux releases and extensions, and reads customer-private content
  directly from the customer's own registry using credentials the customer has
  registered with it.

Omni users — whether on the hosted or on-premises deployment — reach Enterprise Image
Factory through their existing Omni session, with no separate credential to manage.

### Authentication

Every interaction with Enterprise Image Factory requires authentication: the web UI,
direct downloads of ISOs, raw disks, and installer images, the PXE stager, and the
machine config a Talos node uses to pull its installer image at install or upgrade time.

This differs from the public Image Factory's registry frontend, which performs an HTTP
redirect to its backing CDN. When authentication is enabled, Enterprise Image Factory
proxies all registry traffic through itself instead of redirecting, so the auth boundary
applies consistently across every frontend.

## What Enterprise Image Factory does not do

A few boundaries are worth stating explicitly, since they're easy to assume incorrectly:

- It does not replace the public Image Factory at `factory.talos.dev`, which is
  unaffected by anything described on this page.
- It does not require an Omni account on the Talos Enterprise Linux Support tier.
- It does not compile or source-build anything on a customer's behalf. Customers bring
  pre-built OCI images for extensions, and a pre-built imager or installer base for a
  custom build; Enterprise Image Factory assembles the final artifacts from those
  declared inputs.
- It does not verify the contents of customer-provided extensions or custom builds.
  Sidero attests to its own build pipeline and what it produced from the declared
  inputs, not to the contents of unverified customer-supplied components.
