Seccomp (secure computing mode) is a Linux kernel feature that restricts the system calls a process can make.
For more details, see the [Kubernetes seccomp tutorial](https://kubernetes.io/docs/tutorials/security/seccomp/).

This guide declares a custom seccomp profile that logs every system call a workload makes, and runs a pod with it.

## Prepare the nodes

Talos Linux writes each seccomp profile declared in the machine configuration to `/var/lib/kubelet/seccomp/profiles/<name>` on the node.
Save one of the following patches as `seccomp-patch.yaml`, depending on the Talos version of the nodes:

<Tabs>
<Tab title="Talos v1.15+">

Talos 1.15 declares each profile in its own [SeccompProfileConfig](../../talos/v1.15/reference/configuration/cri/seccompprofileconfig) document:

```yaml
apiVersion: v1alpha1
kind: SeccompProfileConfig
name: audit.json
profile:
  defaultAction: SCMP_ACT_LOG
```

The `.machine.seccompProfiles` field still works in Talos 1.15, but it is deprecated.
A `SeccompProfileConfig` document can't use the name of a profile that `.machine.seccompProfiles` already declares.

</Tab>
<Tab title="Talos < v1.15">

Earlier Talos versions declare the profiles in the `.machine.seccompProfiles` field:

```yaml
machine:
  seccompProfiles:
    - name: audit.json
      value:
        defaultAction: SCMP_ACT_LOG
```

</Tab>
</Tabs>

Apply the patch to the nodes:

```bash
talosctl -n <node-ip> patch machineconfig --patch @seccomp-patch.yaml
```

Check that the profile exists:

```bash
talosctl -n <node-ip> get seccompprofiles
```

The output is similar to the following:

```text
NODE       NAMESPACE   TYPE             ID           VERSION
10.5.0.3   cri         SeccompProfile   audit.json   1
```

To view the content of the profile, read the file on the node:

```bash
talosctl -n <node-ip> read /var/lib/kubelet/seccomp/profiles/audit.json
```

The output is the profile in JSON:

```text
{"defaultAction":"SCMP_ACT_LOG"}
```

## Run a workload with the profile

Pods use a profile from the node by setting a `Localhost` seccomp profile in their `securityContext`.
The `localhostProfile` path is relative to `/var/lib/kubelet/seccomp`, so it starts with `profiles/`:

```yaml
spec:
  securityContext:
    seccompProfile:
      type: Localhost
      localhostProfile: profiles/audit.json
```

The example pod from the [Kubernetes seccomp tutorial](https://kubernetes.io/docs/tutorials/security/seccomp/) uses this profile.
Deploy it:

```bash
kubectl apply -f https://k8s.io/examples/pods/security/seccomp/ga/audit-pod.yaml
```

Talos Linux records the system calls logged by the profile in the `auditd` service log.
View them:

```bash
talosctl -n <node-ip> logs auditd --follow
```

The output is similar to the following:


On Talos 1.8 and earlier, which have no `auditd` service, the system calls are in the kernel log instead.
View them with `talosctl -n <node-ip> dmesg --follow`.

## Clean up

Delete the example pod:

```bash
kubectl delete pod audit-pod
```
